# 闇鍋指名手配 — 公開用

巡遊者3人・ロスレコ6個・挑戦する塔を抽選する静的Webアプリです。`index.html`、`script.js`、`style.css`、`characters.json`、`equipments.json` を同じディレクトリに配置してください。外部サーバーやユーザー登録は不要です（JSONを `fetch` で読むため、閲覧はGitHub PagesなどのHTTP(S)配信を利用してください）。

## 共通検索・属性絞り込み

- 「抽選対象を探す」にある**検索欄は1つ**で、巡遊者とロスレコの両方を対象とします。
- **部分一致**で検索します。巡遊者は `name`、ロスレコは `title` と `source` が対象です。`source: null` や未設定でも動作します。英字の大文字・小文字および全角・半角の一部表記揺れを吸収します。
- 7属性（**火、水、風、地、光、闇、無属性**）をボタンで絞り込めます。複数押すとそのうちどれかに一致する項目を表示し、検索文字列がある場合は両条件を満たす項目だけ表示します。
- 押された属性ボタンをもう一度押すと解除します。「条件をクリア」で検索と属性絞り込みの両方を解除します。
- **検索・属性絞り込みのどちらかが有効な間**、一括操作のボタン表示は「表示項目を全選択」「表示項目を全解除」に切り替わります。操作対象は**その時点で表示されている該当種類の項目のみ**です。非表示の項目は変更しません。
- 条件がすべて解除されている場合のみ「全選択」「全解除」を表示し、該当種類の全項目を操作します。
- 一覧の絞り込みは**抽選する候補を限定しません**。抽選は表示・非表示に関係なく、チェック済みのすべての項目から行います。

## 選択状態の保存

- 初回アクセス時はすべて選択済みです。チェック変更、全選択・全解除はブラウザの `localStorage` に自動保存されます。
- 保存されるのは**未選択の項目ID**だけです。JSONに新しく追加された項目は自動的に**選択済み**になります。
- 同じブラウザ・同じサイトで再び開くと選択状態を復元します。別の端末やブラウザとは同期しません。
- 検索文字列・属性ボタンの選択は保存しません。ページを再読み込みすると絞り込みは解除されますが、チェック状態は保存されています。
- 絞り込みのない状態で「全選択」を押すと、その種類の未選択IDの保存記録をクリアします。追加の初期化ボタンはありません。

## JSONの編集

`characters.json` の各要素には `id`, `name`, `attribute`、`equipments.json` の各要素には `id`, `title`, `source`, `attribute` を設定します。

```json
{ "id": "char_042", "name": "新しい巡遊者", "attribute": "火" }
{ "id": "equip_105", "title": "新しいロスレコ", "source": "イベント", "attribute": "" }
```

- 新しい項目には過去に使用していない**固有ID**を指定してください。同じ種類で重複IDを使わないでください。
- 既存項目のIDは変更しないでください。並び順・名称・属性を更新しても、同じIDならチェック状態が維持されます。
- JSONから削除したIDの未選択記録は残るため、同じIDで再追加すれば以前の状態が戻ります。ただし、その種類の絞り込みなしの「全選択」で記録はクリアされます。
- 無属性は `attribute` に `""`, `"無"`, `"無属性"` のいずれを指定しても同じ扱いです。
- IDがない項目は名称を暫定キーとして扱うため、名称を変更すると選択状態が維持されません。固有IDを必ず設定する運用を推奨します。

保存キー：`yaminabe-unselected-v1`（以前の選択状態保存対応版と共通）

## 画面表示・説明パネル

- 「闇鍋指名手配とは？」「使い方」はそれぞれクリック／タップで折り畳めます。初回は両方とも開いています。
- 折り畳み状態は `localStorage`（`yaminabe-info-panels-v1`）にセクション別に保存され、次回も復元されます。巡遊者・ロスレコの選択状態とは別に管理します。
- 抽選後は「挑戦ステージ」を横長の欄に表示し、巡遊者を横3列、ロスレコを横3列×2段で表示します。スマートフォンでも3列表示を維持し、文字は折り返します。
- 属性ボタン「無」は無属性の略記です（内部的な属性値は `無属性`）。
